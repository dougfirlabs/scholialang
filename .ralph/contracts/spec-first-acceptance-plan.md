# j03 → j04: spec-first acceptance without a circular implementation dependency

Private implementation plan, 2026-09-05. No launch, product modification, merge or release is performed by this document. The detailed Map/Event/Task policy remains the recorded candidate proposal pending morning semantic review. Cloud is excluded.

## Decision

Accept j03 as an exact **normative producer contract**, not as proof that an unimplemented core already accepts the new kinds. Keep its complete legacy implementation parity gate against pinned core `192a5176caddd3150caa08b8589314ae3ecc525f`. Add a standalone, index-driven new-spec generation/fixture-integrity gate. In j04, require actual core execution of the exact accepted j03 fixture corpus and full current catalog/field parity. Parent PRD03's combined runtime/package gate closes only after that consumer receipt. No required case is skipped, moved to xfail, or represented as passing before its owning implementation exists.

This is an existing repository pattern, not a new waiver: `tests/test_v062_action_recorded_conformance.py` explicitly says its integrity tests do not import a validator, the spec lands before downstream ports, and implementation repositories execute the same JSON expectations.

### One existing documentation gap discovered during this inspection

Against exact core 0.7.2, the legacy index lacks three fields already present in canonical `KIND_SPECIFIC_FIELDS`: Observation.fingerprint, Uncertainty.on, Confidence.on. Existing tests compare kind sets, not complete field sets, so the baseline is green despite these omissions.

Keep the historical index frozen in this wave, but include these already-supported fields in the **new current** projection with their existing definitions. This is documentation parity repair, not new language semantics. Do not require the new index's 32 legacy entries to be byte-identical to an incomplete old index; instead preserve their semantic behavior, check full current field parity against real core, and retain frozen historical hashes/corpora. Record the three corrections explicitly to avoid misattributing them to new kinds.
